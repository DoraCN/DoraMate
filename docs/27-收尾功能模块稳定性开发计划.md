- **门禁转绿**：依赖残留诊断和 E2E 回归的数据与守护
- **v1.0 打包**：依赖门禁转绿的结果认证

## 阶段一：LocalAgent 残留诊断

### 目标

将 LocalAgent 从"被动善后"升级为"主动诊断 + 启动自检"，使系统在进程异常退出、端口冲突、资源泄漏等场景下可自检、可报告、可恢复。

### 涉及文件

| 文件 | 改动类型 |
|------|---------|
| `doramate-localagent/src/main.rs` | 新增路由 + 逻辑 |
| `doramate-frontend/src/utils/api.rs` | 新增 API 客户端方法 |
| `doramate-frontend/src/components/status_panel.rs` | 可选的诊断信息展示 |

### 具体实施步骤

#### Step 1：新增 `/api/diagnose` 端点

在 `doramate-localagent/src/main.rs` 中新增：

```rust
// 新增数据结构
#[derive(Serialize)]
struct DiagnoseResponse {
    localagent: LocalAgentStatus,
    dora_cli: DoraCliStatus,
    port_52100: PortStatus,
    residual_processes: Vec<ResidualProcess>,
    stale_directories: Vec<StaleDirectory>,
    recommendations: Vec<String>,
}

#[derive(Serialize)]
struct LocalAgentStatus {
    pid: u32,
    uptime_seconds: u64,
    memory_mb: u64,
}

#[derive(Serialize)]
struct DoraCliStatus {
    installed: bool,
    version: String,
    last_known_workspace: String,
}

#[derive(Serialize)]
struct PortStatus {
    in_use: bool,
    owning_pid: Option<u32>,
    owning_process: Option<String>,
}

#[derive(Serialize)]
struct ResidualProcess {
    pid: u32,
    name: String,
    command_line: String,
    cpu_usage: f64,
    memory_mb: u64,
    is_dora_related: bool,
}
```

诊断端点应执行以下检查：

1. **LocalAgent 自身诊断**：PID、运行时间、内存占用
2. **端口诊断**：使用 `TcpClient` 或 `netstat` 扫描 52100 端口是否被占用，占用者是谁
3. **残留进程扫描**：扫描系统中所有含 `dora`、`doramate`、`CSharpNode` 等关键词的进程，返回 PID、名称、资源占用
4. **残留目录检测**：检查 `out/`、`doramate-session-*` 等临时目录是否存在
5. **一致性检查**：比较本地缓存的状态表与实际进程列表，标记不一致的条目
6. **健康建议**：基于以上检查给出可操作建议（如"发现 3 个残留进程，建议执行 cleanup"）

路由注册：

```rust
.route("/api/diagnose", get(diagnose_handler))
```

#### Step 2：LocalAgent 启动自检

在 `main.rs` 的 `main()` 函数中，服务启动前增加启动自检流程：

```rust
fn startup_self_check() -> Vec<String> {
    let mut warnings = Vec::new();
    
    // 1. 端口冲突检测
    if let Ok(in_use) = is_port_in_use(52100) {
        if in_use { warnings.push("Port 52100 already in use".into()); }
    }
    
    // 2. 残留进程检测
    let residual = find_dora_related_processes();
    if !residual.is_empty() {
        warnings.push(format!("Found {} residual Dora process(es)", residual.len()));
    }
    
    // 3. 临时目录清理
    let stale_dirs = find_stale_working_directories();
    if !stale_dirs.is_empty() {
        warnings.push(format!("Found {} stale working director(ies)", stale_dirs.len()));
    }
    
    warnings
}
```

启动自检结果应：
- 记录到日志（`tracing::warn!`）
- 写入内存中的诊断缓存（可通过 `/api/diagnose` 查询）
- 如果存在严重问题（如端口占用），应阻止启动并给出明确错误

#### Step 3：提供 `--cleanup` 命令行模式

新增 CLI 参数，使 LocalAgent 可以以"清理模式"运行：

```rust
enum CliMode {
    Normal,
    Cleanup,       // 清理所有 Dora 相关进程和临时文件后退出
    Diagnose,       // 执行诊断输出后退出
    ForceKill,      // 强制终止所有 Dora 相关进程后退出
}
```

清理模式执行：
1. 扫描并终止所有含 `dora`、`doramate`、`CSharpNode` 的进程
2. 清理 `out/`、`doramate-session-*` 目录
3. 输出清理结果摘要

#### Step 4：前端诊断面板

在 `status_panel.rs` 中新增诊断信息展示区域（可选，可后续再做）：
- 显示 `/api/diagnose` 返回的信息
- 提供"一键清理"按钮
- 当检测到异常状态时给出提示

#### Step 5：测试

在 `main.rs` 的 `#[cfg(test)]` 中添加：
- `test_diagnose_endpoint_returns_valid_schema`
- `test_startup_self_check_without_conflicts`
- `test_residual_process_scanning`
- `test_cleanup_mode_dry_run`

### 验收标准

- [x] `GET /api/diagnose` 返回完整的诊断信息，包含端口、进程、目录、建议四个维度
- [x] LocalAgent 启动时自动检测端口冲突和残留进程，并输出 `warn` 级别日志
- [x] `doramate-localagent --cleanup` 可清理所有 Dora 相关残留进程和临时文件
- [x] 诊断信息可用性不依赖外部工具（仅依赖 `tasklist` / `netstat` 等 Windows 内置命令）
- [x] 相关单元测试通过

## 阶段三：E2E 回归测试

建立覆盖"前端 + LocalAgent + Dora CLI + 节点执行"全链路的 E2E 测试套件，将现有的 smoke 脚本中隐式断言升级为显式测试用例，并集成到 CI 中。

### 具体实施步骤

#### Step 1：安装 Pester 测试框架

Pester 是 PowerShell 的 BDD 测试框架，Windows 自带或可通过 `Install-Module` 安装：

```powershell

```

在 CI 环境中，可在 workflow 中预装：

#### Step 2：编写 E2E 测试套件

创建 `tests/e2e/LocalAgentE2E.Tests.ps1`，包含以下测试场景：

```powershell
BeforeAll {
    $script:agent = @{
        BaseUrl = "http://127.0.0.1:52100/api"
        Process = $null
    }
    # 启动 LocalAgent
    $script:agent.Process = Start-Process -FilePath "doramate-localagent.exe" -PassThru
    Start-Sleep -Seconds 2
}

Describe "LocalAgent Health" {
    It "GET /api/health should return 200" {
        $response = Invoke-RestMethod "$($script:agent.BaseUrl)/health"
        $response.status | Should -Be "ok"
    }
}

Describe "LocalAgent Diagnose" {
    It "GET /api/diagnose should return valid schema" {
        $response = Invoke-RestMethod "$($script:agent.BaseUrl)/diagnose" -ErrorAction Stop
        $response.PSObject.Properties.Name | Should -Contain "localagent"
        $response.PSObject.Properties.Name | Should -Contain "port_52100"
        $response.PSObject.Properties.Name | Should -Contain "residual_processes"
        $response.localagent.pid | Should -BeGreaterThan 0
    }
}

Describe "Dataflow Run-Stop" {
    It "POST /api/run should return a process_id" {
        $body = @{ yaml_content = $testDataflowYaml } | ConvertTo-Json
        $response = Invoke-RestMethod "$($script:agent.BaseUrl)/run" `
            -Method Post -Body $body -ContentType "application/json"
        $response.process_id | Should -Not -BeNullOrEmpty
        $script:processId = $response.process_id
    }

    It "GET /api/status/:process_id should eventually report Running" {
        $maxRetries = 10
        $running = $false
        for ($i = 0; $i -lt $maxRetries; $i++) {
            $status = Invoke-RestMethod "$($script:agent.BaseUrl)/status/$($script:processId)"
            if ($status.status -eq "Running") {
                $running = $true
                break
            }
            Start-Sleep -Seconds 1
        }
        $running | Should -Be $true
    }

    It "POST /api/stop/:process_id should succeed" {
        $response = Invoke-RestMethod "$($script:agent.BaseUrl)/stop/$($script:processId)" `
            -Method Post
        $response.status | Should -Be "stopped"
    }
}

Describe "Residual Cleanup" {
    It "After stop, there should be no Dora-related residual processes" {
        Start-Sleep -Seconds 2
        $diagnose = Invoke-RestMethod "$($script:agent.BaseUrl)/diagnose"
        $diagnose.residual_processes.Count | Should -Be 0
    }
}

AfterAll {
    if ($script:agent.Process -and !$script:agent.Process.HasExited) {
        $script:agent.Process.Kill()
    }
}
```

测试场景清单：

| 场景 | 描述 | 优先级 |
|------|------|--------|
| Health probing | 验证 `/api/health` 返回正确 | P0 |
| 诊断端点 | 验证 `/api/diagnose` 返回结构完整 | P0 |
| 干净启动 | 启动时无残留进程 | P0 |
| 数据流 run | 正常 YAML 启动返回 process_id | P0 |
| 状态同步 | run 后状态最终变为 Running | P0 |
| 数据流 stop | stop 后状态变为 Stopped | P0 |
| 幂等 stop | 对已停止的进程再 stop 不应报错 | P1 |
| 无效 YAML | 提交无效 YAML 应返回明确错误码 | P1 |
| 重复 run | 已运行中再 run 应返回合理错误 | P1 |
| 残留清零 | stop 后无残留进程 | P0 |
| WebSocket 状态流 | WebSocket 推送的状态与 HTTP 一致 | P1 |
| 并发 run/stop | 快速交替 run/stop 不产生残留 | P2 |

### 具体实施步骤

#### Step 1：Failure Triage（数据收集阶段）

执行一次标准门禁（50 轮），收集所有失败日志：

```powershell
# 启用详细日志
$env:RUST_LOG = "debug"
./scripts/release-gate-local-runtime-standard.ps1 -Rounds 50
```

对每次失败按以下模板分类记录到 `out/release-gates/triage-50r.csv`：

```
round, phase, error_code, error_message, root_cause_category, runtime_version, dotnet_version
1,    run,   TIMEOUT,   "dora start timed out",    TIMING,   dora 0.5.0,  8.0.4
3,    stop,  RESIDUAL,  "2 residual nodes found",   CLEANUP,  dora 0.5.0,  8.0.4
...
```

根因分类体系：

| 分类 | 典型模式 | 标签 |
|------|---------|------|
| TIMING | 超时类失败（启动慢、停止慢） | 可控 |
| CLEANUP | 残留进程类失败 | 可控 |
| DORA_BUG | Dora CLI 自身崩溃或异常退出 | 低可控 |
| ENV | CI 环境问题（磁盘、网络、资源） | 不可控 |
| CSharp_AOT | C# NativeAOT 启动失败 | 中可控 |
| UNKNOWN | 无法归类的失败 | 需调查 |

#### Step 2：按 Pareto 原则逐个击破

基于步骤 1 的分类数据，优先修复占比最高的根因。

**常见修复方向：**

| 根因 | 典型修复策略 | 涉及代码 |
|------|-------------|---------|
| TIIMING | 增加超时、增加重试次数、优化轮询间隔 | `smoke-localagent-run-status-stop.ps1` 参数 |
| CLEANUP | 加强 stop 后的确认轮询、增加 `cleanup_stale_node_processes` 调用 | `main.rs:stop_handler` |
| DORA_BUG | 增加兼容性处理、降级策略、更明确的错误码 | `main.rs` run/stop 逻辑 |
| CSharp_AOT | 预加热（pre-jit）、增加启动探测重试 | `main.rs` run readiness 检查 |

具体到 `main.rs` 的修改：

```rust
// 1. run 超时优化：增加阶梯式超时
async fn run_handler(...) {
    // 第一次快速尝试（5s）
    // 如果失败，进行第二次等待（10s）
    // 如果再次失败，进行第三次长等待（20s），之后报错
    // 每次失败输出详细的进程状态快照
}

// 2. stop 确认增强：使用进程扫描 + 状态表双重确认
async fn stop_handler(...) {
    // 1. 执行 dora stop
    // 2. 轮询状态表等待 Running -> Stopped（15s 超时）
    // 3. 进程级确认：tasklist 确认所有节点进程已退出
    // 4. 如果进程残留，执行 cleanup_stale_node_processes
    // 5. 最终确认
}

// 3. 状态一致性：增加进程扫描旁路验证
async fn status_handler(...) {
    // 返回状态时，如果缓存状态为 Running，但进程扫描发现已无存活节点
    // 则标记为 stale 并返回 Stopped（经过确认阈值）
}
```

#### Step 2：ZIP 打包脚本

创建 `scripts/package-zip.ps1`：

```powershell
param(
    [string]$Version = (Get-Content (Join-Path $PSScriptRoot "..\VERSION") -Raw).Trim(),
    [string]$OutputDir = (Join-Path $PSScriptRoot "..\out\dist")
)

$repoRoot = (Resolve-Path (Join-Path $PSScriptRoot "..")).Path
$distDir = Join-Path $OutputDir "doramate-$Version"

# 创建目录结构
@("bin", "frontend", "examples", "tools") | ForEach-Object {
    New-Item -ItemType Directory -Path (Join-Path $distDir $_) -Force | Out-Null
}

# 1. LocalAgent 二进制
Copy-Item (Join-Path $repoRoot "target\release\doramate-localagent.exe") (Join-Path $distDir "bin\")

# 2. 前端 WASM
Copy-Item (Join-Path $repoRoot "doramate-frontend\dist\*") (Join-Path $distDir "frontend\") -Recurse

# 3. Dora CLI
Copy-Item (Join-Path $repoRoot "dora-api-csharp\third_party\dora\target\release\dora.exe") (Join-Path $distDir "bin\")

# 4. 示例配置
Copy-Item (Join-Path $repoRoot "doramate-examples\*.yml") (Join-Path $distDir "examples\")
Copy-Item (Join-Path $repoRoot "doramate-examples\*.layout.json") (Join-Path $distDir "examples\")

# 5. 启动脚本
@'
@echo off
start /B doramate-localagent.exe
start http://127.0.0.1:52100
'@ | Out-File (Join-Path $distDir "start.cmd") -Encoding ascii

# 6. README
@"
DoraMate v$Version
==================
Usage: start.cmd or bin/doramate-localagent.exe
"@ | Out-File (Join-Path $distDir "README.txt") -Encoding ascii

# 打包 ZIP
Compress-Archive -Path "$distDir\*" -DestinationPath "$OutputDir\doramate-$Version-win-x64.zip" -Force
Write-Host "Package created: $OutputDir\doramate-$Version-win-x64.zip"
```

#### Step 3：NSIS 安装包脚本

创建 `scripts/package-installer.nsi`（简化版）：

```nsis
!define PRODUCT_NAME "DoraMate"
!define PRODUCT_VERSION "0.9.0"
!define PRODUCT_PUBLISHER "DoraMate Team"

Name "${PRODUCT_NAME} ${PRODUCT_VERSION}"
OutFile "doramate-${PRODUCT_VERSION}-setup.exe"
InstallDir "$PROGRAMFILES64\DoraMate"

Section "Install"
  SetOutPath "$INSTDIR"
  
  File /r "dist\doramate-${PRODUCT_VERSION}\*"
  
  CreateShortCut "$DESKTOP\DoraMate.lnk" "$INSTDIR\start.cmd"
  CreateDirectory "$SMPROGRAMS\DoraMate"
  CreateShortCut "$SMPROGRAMS\DoraMate\DoraMate.lnk" "$INSTDIR\start.cmd"
  CreateShortCut "$SMPROGRAMS\DoraMate\Uninstall.lnk" "$INSTDIR\uninstall.exe"
  
  WriteUninstaller "$INSTDIR\uninstall.exe"
  WriteRegStr HKLM "Software\Microsoft\Windows\CurrentVersion\Uninstall\DoraMate" "DisplayName" "DoraMate"
  WriteRegStr HKLM "Software\Microsoft\Windows\CurrentVersion\Uninstall\DoraMate" "UninstallString" "$INSTDIR\uninstall.exe"
SectionEnd

Section "Uninstall"
  RMDir /r "$INSTDIR"
  Delete "$DESKTOP\DoraMate.lnk"
  RMDir /r "$SMPROGRAMS\DoraMate"
  DeleteRegKey HKLM "Software\Microsoft\Windows\CurrentVersion\Uninstall\DoraMate"
SectionEnd
```

#### Step 4：一键构建脚本

创建 `scripts/build-release.ps1`：

```powershell
[CmdletBinding()]
param([switch]$SkipTests)

$ErrorActionPreference = "Stop"
$repoRoot = (Resolve-Path (Join-Path $PSScriptRoot "..")).Path
$version = (Get-Content (Join-Path $repoRoot "VERSION") -Raw).Trim()

Write-Host "=== DoraMate v$version Release Build ==="

# 1. 版本一致性检查
$cargoVersion = (Select-Xml -Path (Join-Path $repoRoot "doramate-localagent\Cargo.toml") `
    -XPath "//package/version").Node.InnerText
if ($cargoVersion -ne $version) {
    throw "Version mismatch: VERSION=$version, Cargo.toml=$cargoVersion"
}

# 2. 运行标准门禁（验证发布质量）
if (-not $SkipTests) {
    Write-Host "Running standard release gate..."
    & (Join-Path $PSScriptRoot "release-gate-local-runtime-standard.ps1") -Rounds 20
    if ($LASTEXITCODE -ne 0) { throw "Release gate failed" }
}

# 3. 构建产物
Write-Host "Building LocalAgent (release)..."
cargo build -p doramate-localagent --release

Write-Host "Building frontend (release)..."
Push-Location (Join-Path $repoRoot "doramate-frontend")
trunk build --release
Pop-Location

Write-Host "Building Dora CLI..."
Push-Location (Join-Path $repoRoot "dora-api-csharp\third_party\dora")
cargo build -p dora-cli --release
Pop-Location

Write-Host "Packaging..."
& (Join-Path $PSScriptRoot "package-zip.ps1") -Version $version

Write-Host "=== Build Complete ==="
Write-Host "Output: out\dist\doramate-$version-win-x64.zip"
```

## 主要风险与应对

### 风险 1：Dora CLI 自身不稳定

**概率**：中 | **影响**：高 | **可控性**：低

Dora CLI（vendored）的 bug 可能导致门禁无法达到 100%。如果发现 Dora CLI 自身的竞态条件或资源泄漏，应对方案：

1. **在 DoraMate 侧加兼容层**：对已知的 Dora CLI 不稳定行为加 retry / workaround
2. **升级 Dora 版本**：跟踪上游修复
3. **降级门禁阈值**：如果确实是上游问题，在文档中说明并设置合理阈值

### 风险 2：Windows CI 环境波动

**概率**：中 | **影响**：中 | **可控性**：低

GitHub Actions 的 Windows runner 存在资源波动（CPU 抢占、磁盘 IO 抖动）。应对方案：

1. 增加超时参数（从 30s 增加到 60s）
2. 首次失败后自动重试
3. 区分"环境失败"和"逻辑失败"，环境失败不计入门禁结果

### 风险 3：NSIS 安装包兼容性

**概率**：低 | **影响**：中 | **可控性**：中

不同 Windows 版本对安装包的行为可能不同。应对方案：

1. 优先做 ZIP 分发，NSIS 作为增强选项
2. 在 Windows 10/11 和 Windows Server 2022 上测试
3. 考虑用 Rust 编写自定义安装器（跨平台，但成本较高）

### 风险 4：.NET 运行时依赖

**概率**：高 | **影响**：中 | **可控性**：高

C# 节点需要用户安装 .NET 8 Runtime，未安装时体验断裂。应对方案：

1. ZIP 包中附带 `dotnet --info` 检测脚本
2. 安装包中提示用户安装 .NET Runtime（提供链接）
3. 考虑捆绑 .NET 8 的修剪版（NativeAOT 发布即可免除依赖，但需要迁移）

### 风险 5：版本协调错误

**概率**：低 | **影响**：高 | **可控性**：中

多组件版本不一致可能导致 API 不兼容。应对方案：

1. `build-release.ps1` 中包含版本一致性检查
2. LocalAgent API 变更时记得更新前端 API 客户端
3. 使用 `VERSION` 作为单一事实来源
