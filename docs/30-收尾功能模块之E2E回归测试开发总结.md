## 背景与目标

在 DoraMate v1.0 就绪路线图中，前四个收尾阶段（残留诊断、C# 模板产品化、门禁转绿、v1.0 打包）都需要一个可靠的质量守护网来防止回归。实施 E2E 回归测试前：

- 现有的 **smoke 脚本**（`smoke-localagent-run-status-stop.ps1`）使用隐式断言，通过退出码判断成功/失败
- 没有统一的测试框架，测试结果缺乏标准化输出
- PR 门禁只运行 cargo unit test + 多轮 smoke，无显式 E2E 断言
- 无定时执行的回归测试，无法跟踪长期稳定性趋势

**阶段三目标**，如计划文档所述：

> 建立覆盖"前端 + LocalAgent + Dora CLI + 节点执行"全链路的 E2E 测试套件，将现有的 smoke 脚本中隐式断言升级为显式测试用例，并集成到 CI 中。

## 实施内容

### 1. Pester 测试套件

创建 `tests/e2e/LocalAgentE2E.Tests.ps1`，使用 Pester 5 BDD 框架，包含 12 个测试场景，按 P0/P1/P2 优先级分类。

**文件结构：**

```
tests/e2e/
└── LocalAgentE2E.Tests.ps1     # 主测试套件（410 行）
```

**生命周期管理：**

| 阶段 | 行为 |
|------|------|
| `BeforeAll` | 检查 curl.exe 可用性 → 检测 LocalAgent 是否运行 → 如未运行自动编译 + 启动 |
| `AfterAll` | 停止由测试套件启动的 LocalAgent 进程 → 无差别清理残留进程 |
| 测试间 | 通过 `$script:ProcessId` 传递状态（run → status → stop → clean） |

**辅助函数（均在 BeforeAll 中定义）：**

| 函数 | 用途 |
|------|------|
| `Get-RepoRoot` | 解析仓库根目录路径 |
| `Get-DataflowYaml` | 读取默认 smoke dataflow YAML |
| `Test-TcpPortOpen` | TCP 端口连通性检查 |
| `Invoke-LocalAgentApi` | 封装 GET/POST 调用 LocalAgent API |
| `Normalize-Status` | 统一状态值规范化（大小写/别名） |
| `Wait-ForDataflowStatus` | 轮询等待数据流达到目标状态 |
| `Start-LocalAgentProcess` | 启动受管理的 LocalAgent 进程 |
| `Stop-LocalAgentProcess` | 停止 LocalAgent 进程 |
| `Test-WebSocketConsistency` | WebSocket 状态流与 HTTP 状态一致性断言 |

### 2. 测试场景清单

#### P0 — PR 门禁核心（8 个测试）

| 场景 | 断言 | 说明 |
|------|------|------|
| `GET /api/health` | `status` = `"ok"` | 服务健康检查 |
| `GET /api/diagnose` schema | 包含 5 个必需字段 | 诊断端点结构完整性 |
| 残留为零 | `residual_processes.Count` = 0 | 干净启动确认 |
| POST `/api/run` | `process_id` 非空 | 数据流启动 |
| 状态同步到 Running | `Reached` = true | 轮询等待状态转换 |
| POST `/api/stop` | `status` = `"stopped"` | 数据流停止 |
| 状态到 Stopped/Idle | `Reached` = true | 最终状态确认 |
| 残留清零 | `residual_processes.Count` = 0 | 停止后无残留 |

#### P1 — 增强测试（4 个测试）

| 场景 | 断言 | 说明 |
|------|------|------|
| 无效 YAML | 返回 error / `success` = false | 错误处理 |
| 未知 process_id stop | 不崩溃 | 幂等性 |
| WebSocket 一致性 | `StateMatch` = true | WS 与 HTTP 状态一致 |
| 并发 run/stop | 残留 = 0 | 快速交替不产生残留 |

### 3. Nightly E2E CI Workflow

新建 `.github/workflows/local-runtime-e2e.yml`：

| 配置项 | 值 |
|--------|-----|
| 触发方式 | 工作日 6:00 UTC (`cron: '0 6 * * 1-5'`) + `workflow_dispatch` |
| Runner | `windows-latest` |
| 超时 | 30 分钟 |
| 前置依赖 | Rust toolchain、.NET 8、Pester 5 |
| 构建步骤 | Vendor Dora → Build Dora CLI → Build Smoke Sample → Build LocalAgent |
| 测试命令 | `Invoke-Pester ./tests/e2e/`（全量 12 个测试） |
| 报告 | 上传 `out/e2e/` 目录 |

在 `.github/workflows/local-runtime-pr-gate.yml` 中新增 `windows-pr-e2e-p0` job：

| 配置项 | 值 |
|--------|-----|
| Job 名 | `windows-pr-e2e-p0` |
| 超时 | 20 分钟 |
| 测试过滤 | `-Tag "P0"`（仅运行 8 个 P0 测试） |
| 失败处理 | `FailedCount > 0` → throw |

此 job 与现有的 `windows-pr-live-smoke` 并行执行，相互独立。

## 关键实现细节

### Pester 5 作用域

在实现过程中遇到的核心问题：Pester 5 将测试执行分为**发现（Discovery）**和**执行（Execution）**两个独立的 session state。

```
┌─────────────────────┐      ┌──────────────────────┐
│   Discovery Scope    │      │   Execution Scope     │
│                     │      │                       │
│  param()            │      │  BeforeAll { }        │
│  Set-StrictMode     │      │  AfterAll { }         │
│  $script:变量       │      │  It { }               │
│  Describe/It 名称   │      │  BeforeEach/AfterEach │
│  BeforeDiscovery { }│      │                       │
└─────────┬───────────┘      └───────────┬───────────┘
          │                              │
          │  脚本级变量/函数              │  无法访问脚本级函数
          │  → 仅用于 Describe/It 名称    │  → 所有辅助函数需在
          │    的发现阶段                  │     BeforeAll 中定义
          └──────────────────────────────┘
```

**表现**：`function Get-RepoRoot { ... }` 定义在脚本级（Describe 之前），在 `Describe` 名称解析时可用，但在 `BeforeAll { Get-RepoRoot }` 中调用会导致 `CommandNotFoundException`。

**解决方案**：将所有执行期需要的辅助函数和变量定义移到 `BeforeAll` 块内部。

```powershell
# ❌ 不可行 — 脚本级函数在执行期不可见
function Invoke-LocalAgentApi { ... }

BeforeAll {
    Invoke-LocalAgentApi   # CommandNotFoundException
}

# ✅ 可行 — BeforeAll 中定义的函数在同文件的所有执行期共享
BeforeAll {
    function Invoke-LocalAgentApi { ... }

    $script:RepoRoot = Get-RepoRoot   # 执行期变量
}

Describe "Health" -Tag "P0" {
    It "GET /api/health" {
        Invoke-LocalAgentApi -Method GET -Path "health"   # 可用
    }
}
```

### Tag 驱动优先级过滤

Pester 5 支持在 `Describe` 或 `It` 级别打 Tag，运行时通过 `-Tag` 参数过滤。

```powershell
# 定义
Describe "Health Endpoint" -Tag "P0" { ... }
Describe "Error Handling" -Tag "P1" { ... }
Describe "Concurrent Operations" -Tag "P2" { ... }

# PR 门禁只跑 P0
Invoke-Pester ./tests/e2e/ -Tag "P0"
# → 12 个测试中发现 8 个 P0，4 个 P1/P2 标记为 NotRun
```

### WebSocket 一致性断言

P1 测试 `WebSocket Status Stream` 实现了以下断言逻辑：

1. 通过 `/api/run` 启动一个数据流
2. 等待状态变为 Running
3. 同时建立 WebSocket 连接 + HTTP polling
4. 在 `WindowSeconds` 窗口内收集 WS 和 HTTP 的状态样本
5. 比较最后一个样本的 `Normalize-Status` 是否一致
6. 清理：停止数据流

```powershell
$wsResult = Test-WebSocketConsistency -ProcessId $wsProcessId -WindowSeconds 5
$wsResult.StateMatch | Should -Be $true
```

| Run-Stop 测试 | 需 CI 环境（依赖 Dora CLI + .NET sample 构建） |

### 已知依赖

E2E 测试套件在 CI 中的前置条件：

1. **Dora CLI**：`dora.exe` 必须在 PATH 中
2. **数据流样本**：`CSharpNode.exe` 必须已编译（`dotnet build -c Release`）
3. **curl.exe**：Windows 自带或通过 Git for Windows 提供
4. **LocalAgent**：debug 或 release 构建

## 与计划规范的差异

| 计划规范 | 实际实现 | 原因 |
|---------|---------|------|
| `tests/e2e/SmokeP0.Tests.ps1` 作为独立文件 | 使用 `-Tag "P0"` 在主文件中过滤 | 避免代码重复，主文件已涵盖所有场景 |
| WebSocket 使用 `Test-StatusStreamConsistency` | 简化为 `Test-WebSocketConsistency` | 减少了不必要字段（source/stale/running_nodes），聚焦状态一致性核心断言 |
| `Invoke-LocalAgentJson` 函数复用 | 内联为 `Invoke-LocalAgentApi` | 测试文件需自包含，不依赖外部脚本 |
| 前端 E2E（WASM 编译 + 浏览器） | 未实现 | 计划中原定为"前端 + LocalAgent"全链路，实际仅覆盖 LocalAgent API + Dora CLI 链路。前端 E2E 需要 WASM 构建和 headless browser 环境，投入产出比低于后端 |

## 使用指南

### 本地运行

```powershell
# 前提：确保 dora CLI 在 PATH 中，smoke sample 已编译

# 1. 安装 Pester 5（如未安装）
Install-Module -Name Pester -Force -SkipPublisherCheck

# 2. 运行全部 E2E 测试
Import-Module Pester -MinimumVersion 5.0.0 -Force
$config = @{ Run = @{ Exit = $true } }
Invoke-Pester ./tests/e2e/LocalAgentE2E.Tests.ps1 -Configuration $config

# 3. 仅运行 P0 门禁测试
Invoke-Pester ./tests/e2e/LocalAgentE2E.Tests.ps1 -Configuration $config -Tag "P0"

# 4. 指定自定义参数
Invoke-Pester ./tests/e2e/LocalAgentE2E.Tests.ps1 -Configuration $config `
    -LocalAgentBaseUrl "http://127.0.0.1:52100/api" `
    -RunTimeoutSeconds 60 `
    -StopTimeoutSeconds 30
```

### CI 运行

```powershell
# Nightly E2E（全量 12 个测试）
# 由 .github/workflows/local-runtime-e2e.yml 触发

# PR 门禁（P0 8 个测试）
# 由 .github/workflows/local-runtime-pr-gate.yml 中的
# windows-pr-e2e-p0 job 执行
```
