# 28 - 收尾功能模块之残留诊断开发总结

> 基于 `docs/27-收尾功能模块稳定性开发计划.md` 阶段一的规划，完成 LocalAgent 残留诊断功能的开发总结。

---

## 1. 开发目标

将 LocalAgent 从"被动善后"升级为"主动诊断 + 启动自检"，使系统在进程异常退出、端口冲突、资源泄漏等场景下可自检、可报告、可恢复。

---

## 2. 改动清单

### 2.1 LocalAgent 侧（`doramate-localagent/src/main.rs`）

| 改动 | 类型 | 说明 |
|------|------|------|
| `CliMode` 枚举 | 新增 | `Normal` / `Cleanup` / `Diagnose` / `ForceKill` 四种运行模式 |
| `DiagnoseResponse` | 新增结构体 | 顶层诊断响应，聚合 7 个维度的诊断信息 |
| `LocalAgentStatus` | 新增结构体 | 自身 PID、运行时长 |
| `DoraCliStatus` | 新增结构体 | Dora CLI 安装状态和版本 |
| `PortStatus` | 新增结构体 | 端口 52100 是否被占用、占用者 PID 和进程名 |
| `ResidualProcessInfo` | 新增结构体 | 残留进程的 PID、名称、是否 Dora 相关 |
| `StaleDirectoryInfo` | 新增结构体 | 残留目录路径和存在时长 |
| `AppState.startup_warnings` | 新增字段 | 存储启动自检产生的警告信息 |
| `LOCALAGENT_PORT` | 新增常量 | 提取端口号到常量 |
| `DORA_PROCESS_KEYWORDS` | 新增常量 | 扫描关键词列表：`dora`, `doramate`, `coordinator`, `CSharpNode` |

#### 新增函数

| 函数 | 签名 | 说明 |
|------|------|------|
| `scan_dora_related_processes()` | `-> Vec<ResidualProcessInfo>` | 扫描系统进程表，匹配关键词返回 Dora 相关进程列表。Windows 用 `tasklist`，Unix 用 `ps` |
| `check_port_52100_owner()` | `-> PortStatus` | 检测端口 52100 占用情况。Windows 用 `netstat -ano`，Unix 用 `lsof` |
| `get_process_name_by_pid(pid)` | `(u32) -> Option<String>` | 通过 PID 反向查询进程名。Windows 用 `tasklist /FI`，Unix 用 `ps` |
| `scan_stale_directories()` | `-> Vec<StaleDirectoryInfo>` | 扫描 CWD 下的 `out/` 和 `doramate-session-*` 目录 |
| `build_diagnose_response(state)` | `(&AppState) -> DiagnoseResponse` | 在 blocking task 中组合所有诊断信息，生成推荐建议 |
| `cleanup_all_residual()` | `-> Vec<String>` | Kill 所有 Dora 相关进程 + 执行 `dora stop --all` |
| `diagnose_handler()` | `-> Json<DiagnoseResponse>` | `GET /api/diagnose` HTTP 端点处理函数 |

## 3. 关键实现细节

### 3.1 CLI 模式分发

`main()` 函数在启动 tracing 后立即解析 CLI 参数，根据模式分流：

- `--diagnose`：构建诊断报告并打印到 stdout 后退出
- `--cleanup`：执行 `cleanup_all_residual()` 后退出
- `--force-kill`：同 cleanup，更直接的命名
- `Normal`：执行启动自检，记录警告，启动 HTTP 服务

### 3.2 启动自检

```rust
// LocalAgent 启动时自动执行：
// 1. 检测端口 52100 是否已被占用
// 2. 扫描系统中有无残留的 Dora 进程
// 3. 结果写入 AppState.startup_warnings
// 4. 日志输出 warnings（不影响启动）
```

### 3.3 跨平台兼容

| 功能 | Windows | Unix |
|------|---------|------|
| 进程扫描 | `tasklist /FO CSV /NH` | `ps -eo pid,comm` |
| 端口检查 | `netstat -ano -p tcp` | `lsof -i :52100 -P -n` |
| 进程名查询 | `tasklist /FI PID eq N /FO CSV /NH` | `ps -p N -o comm=` |
| 进程终止 | `taskkill /F /IM` | `kill -9` |

### 3.4 诊断报告格式

`GET /api/diagnose` 返回 JSON：

```json
{
  "localagent": { "pid": 12345, "uptime_seconds": 3600 },
  "dora_cli": { "installed": true, "version": "0.5.0" },
  "port_52100": { "in_use": false, "owning_pid": null, "owning_process": null },
  "residual_processes": [
    { "pid": 9999, "name": "dora-daemon.exe", "is_dora_related": true }
  ],
  "stale_directories": [
    { "path": "C:/out/", "age_seconds": 7200 }
  ],
  "startup_warnings": [],
  "recommendations": [
    "Found 1 Dora-related process(es). Run 'doramate-localagent --cleanup' to clean them."
  ]
}
```

## 5. 与计划的差异

| 计划项 | 计划状态 | 实际状态 | 说明 |
|--------|---------|---------|------|
| `GET /api/diagnose` 端点 | ✅ | ✅ 已实现 | 返回 7 个维度诊断信息 |
| 启动自检 | ✅ | ✅ 已实现 | 端口 + 进程双检，结果存入 AppState |
| `--cleanup` 模式 | ✅ | ✅ 已实现 | 含 `dora stop --all` |
| `--diagnose` CLI 模式 | ✅ | ✅ 已实现 | 打印完整可读报告后退出 |
| `--force-kill` 模式 | ✅ | ✅ 已实现 | Cleanup 的别名 |
| 前端诊断面板 | 可选，后续再做 | ❌ 未实现 | 保持前端变更最小化 |
| 启动时严重问题阻止启动 | 考虑中 | ❌ 未实现 | 当前仅 warn 不阻止（避免影响正常启动） |

未实现项说明：
- **前端诊断面板**：计划中标记为可选，需先在状态面板中增加 UI 组件。当前前端仅暴露 API 客户端方法，UI 部分后续迭代。
- **严重问题阻止启动**：当前策略是 warn 而非 abort，因为端口占用可能在服务绑定前释放，更符合 LocalAgent 作为本地工具的容错预期。

## 6. 使用方式

```bash
# 正常启动（含启动自检，不影响服务）
doramate-localagent.exe

# CLI 诊断模式
doramate-localagent.exe --diagnose
# 输出：
# === DoraMate LocalAgent Diagnose ===
# LocalAgent PID: 12345
# Dora CLI installed: true
# ...

# 清理所有残留进程
doramate-localagent.exe --cleanup

# API 调用
curl http://127.0.0.1:52100/api/diagnose

# 前端调用（已在 api.rs 中暴露）
use crate::utils::api::diagnose;
let result = diagnose().await;
```
