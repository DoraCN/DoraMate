# 21 - 本地运行状态接口契约

> 目标：把 DoraMate 当前本地运行主链路里最容易漂移的 `status` 口径先固定下来，作为后续 `status` / `stop` 加固的实现基线。

## 1. 状态枚举

LocalAgent 与前端统一使用以下状态集合：

- `Idle`
- `Starting`
- `Running`
- `Stopping`
- `Stopped`
- `Failed`
- `Unknown`

当前语义约定如下：

- `Idle`：LocalAgent 中不存在该 `process_id` 的活动注册信息。
- `Starting`：运行请求已被接受，但在启动确认窗口内尚未探测到运行中的节点进程。
- `Running`：已探测到至少一个运行中的节点进程。
- `Stopping`：停止请求已受理，仍存在未退出的节点进程。
- `Stopped`：未探测到运行中的节点进程，且流程已完成停止或明确退出。
- `Failed`：LocalAgent 已记录到当前流程的失败态，例如 stop 失败后的结构化失败提示。
- `Unknown`：当前状态无法可靠判断，例如状态探测依赖的 YAML 解析失败。

## 2. 状态来源

`DataflowStatusResponse.source` 当前固定为以下枚举之一：

- `registry`
- `process_scan`
- `registry_and_process_scan`

当前版本主要使用：

- `registry`：仅来自 LocalAgent 运行注册表的判断。
- `registry_and_process_scan`：同时结合注册表状态提示和节点进程扫描结果。

## 3. HTTP / WebSocket 响应结构

`GET /api/status/:process_id` 与 `GET /api/status-stream/:process_id` 使用同一份结构：

```json
{
  "process_id": "example-process-id",
  "status": "Running",
  "uptime_seconds": 12,
  "total_nodes": 4,
  "running_nodes": 3,
  "error_nodes": 1,
  "node_details": [
    {
      "id": "camera",
      "node_type": "opencv-video-capture",
      "is_running": true
    }
  ],
  "last_updated_at": "2026-04-18T12:00:00Z",
  "source": "registry_and_process_scan",
  "stale": false,
  "message": "Detected 3 running node(s)."
}
```

字段语义：

- `status`：统一生命周期状态。
- `last_updated_at`：当前状态快照生成时间。
- `source`：当前状态的主要来源。
- `stale`：当前状态是否带有降级或不完全可信语义。
- `message`：给前端和日志使用的结构化说明文本。

## 4. 当前实现边界

这份契约先固定“返回什么”，尚未完成“状态如何长期维护”的全部收口。当前仍有以下边界待后续阶段继续推进：

- LocalAgent 当前已具备最小运行注册表快照，会缓存最近一次成功状态探测结果，并在探测失败时回退到最后已知状态；但它仍不是完整的长期状态治理层。
- `run` 当前已具备最小启动确认窗口：`dora start` 返回成功后，LocalAgent 会在短确认窗口内验证节点是否进入运行态，失败时写回 `Failed` 并返回 `START_CONFIRMATION_FAILED`。
- `stop` 当前已具备最小两阶段确认窗口：`dora stop` 成功后会进入确认轮询，并在超时后执行一次有限补救；但更细的残留分类和更强的补救策略仍待后续推进。
- `Unknown` 目前主要用于状态探测失败场景，后续还应继续细化 stale / degraded 语义。

## 5. 兼容性说明

前端当前仍兼容旧状态字符串：

- `running`
- `stopped`
- `not_found`
- `unknown`

但从本契约开始，新的标准返回值应以上述统一状态枚举为准。
