# 22 - 本地运行发布门禁

> 目标：把 DoraMate 当前 `run / status / stop` 主链路的发布前检查，从“手工感觉可用”收口成“有固定脚本、有固定样例、有固定输出”的最小门禁。

## 1. 当前门禁组成

当前 Windows 优先的本地运行发布门禁由两部分组成：

1. 关键单元测试
2. `run -> status -> stop` live smoke

对应脚本：

- `scripts/release-gate-local-runtime.ps1`
- `scripts/release-gate-local-runtime-standard.ps1`
- `scripts/smoke-localagent-run-status-stop.ps1`

对应 CI workflow：

- `.github/workflows/local-runtime-standard-release-gate.yml`

## 2. 默认样例

当前 live smoke 默认使用：

- `dora-api-csharp/samples/csharp-dataflow/smoke.dataflow.yml`

选择这个样例的原因：

- 相比摄像头 / OpenCV / YOLO 示例，它依赖更少
- 没有 GUI 观察依赖
- 能覆盖 DoraMate 真正关心的本地运行主链路
- 当前仓库里已有对应构建产物与样例资产
- live smoke 不再把 `build:` 步骤直接混进 `run` 主链路，减少首次构建噪音

## 3. 执行方式

门禁脚本当前统一按 `pwsh` 运行验证，不建议再用 `powershell.exe` 调用，否则在本机上可能遇到托管 LocalAgent 请求阶段的兼容性差异。

### 仅跑 live smoke

```powershell
pwsh ./scripts/smoke-localagent-run-status-stop.ps1
```

常用参数：

```powershell
pwsh ./scripts/smoke-localagent-run-status-stop.ps1 `
  -Rounds 5 `
  -DataflowPath .\dora-api-csharp\samples\csharp-dataflow\dataflow.yml
```

如果需要保留样例工作目录里的 `out/` 现场用于排查，可以显式关闭这部分清理：

```powershell
pwsh ./scripts/smoke-localagent-run-status-stop.ps1 `
  -KeepWorkingDirOut
```

### 跑完整本地发布门禁

```powershell
pwsh ./scripts/release-gate-local-runtime.ps1
```

常用参数：

```powershell
pwsh ./scripts/release-gate-local-runtime.ps1 `
  -Rounds 5
```

### 跑标准发布门禁

标准发布门禁脚本默认按 20 轮 smoke 执行，并要求满足固定通过阈值；如需加严，可把轮次提高到 50 轮以内：

```powershell
pwsh ./scripts/release-gate-local-runtime-standard.ps1
```

```powershell
pwsh ./scripts/release-gate-local-runtime-standard.ps1 `
  -Rounds 30
```

这个标准入口默认会包含：

- `doramate-localagent/cargo test --locked`
- `doramate-frontend/cargo test --locked`
- 20 到 50 轮标准 smoke

如果只想看 live smoke，可以跳过单元测试：

```powershell
pwsh ./scripts/release-gate-local-runtime.ps1 `
  -SkipLocalAgentTests `
  -SkipFrontendTests
```

## 4. 当前检查内容

`scripts/release-gate-local-runtime.ps1` 当前会执行：

- `doramate-localagent/cargo test --locked`
- `doramate-frontend/cargo test --locked`
- 调用 `scripts/smoke-localagent-run-status-stop.ps1`

`scripts/smoke-localagent-run-status-stop.ps1` 当前会在每一轮中检查：

1. 通过 LocalAgent `POST /api/run` 发起运行
2. 轮询 `GET /api/status/:process_id`，确认进入 `Running`
3. 调用 `POST /api/stop`
4. 轮询 `GET /api/status/:process_id`，确认进入 `Stopped` 或 `Idle`
5. 在脚本退出前自动清理工作目录下的 `doramate_*.yml` 临时 dataflow 文件，避免历史残留持续堆积
6. 默认清理工作目录 `out/` 下的 Dora 运行产物，保留 `.gitignore`；如果传入 `-KeepWorkingDirOut`，则跳过这一步

为了兼容当前仓库里仍可能存在的新旧状态响应混用，smoke 当前会同时接受以下状态别名：

- 运行态：`Running` / `running`
- 最终停止态：`Stopped` / `stopped` / `Idle` / `idle` / `not_found`

## 5. 通过标准

当前 smoke 默认要求全部轮次满足以下条件：

- `run` API 返回成功
- 状态确认阶段进入 `Running`
- `stop` API 返回成功
- 最终状态确认进入 `Stopped` 或 `Idle`
- 不存在 residual failure

只要任一轮失败，smoke 脚本会以非零结果退出。

完整发布门禁则要求：

- LocalAgent 单元测试通过
- Frontend 单元测试通过
- live smoke 通过

标准发布门禁当前固化为以下阈值：

- smoke 轮次必须在 `20` 到 `50` 之间
- `run_success_rate >= 100%`
- `status_confirmation_rate >= 100%`
- `stop_success_rate >= 100%`
- `residual_failures <= 0`
- `cleanup_failed_count + out_cleanup_failed_count <= 0`
- 轮次必须全部完成，不允许中途短跑结束

对应实现方式：

- `scripts/release-gate-local-runtime-standard.ps1`：固定启用标准发布档位
- `scripts/release-gate-local-runtime.ps1 -UseStandardReleaseProfile`：走同一套阈值，但保留主脚本入口
- `scripts/smoke-localagent-run-status-stop.ps1`：支持显式传入阈值，并把阈值与评估结果写入 summary JSON
- `.github/workflows/local-runtime-standard-release-gate.yml`：在 Windows runner 上手动触发标准发布门禁，并上传 `out/release-gates/` 结果

## 6. 输出文件

所有门禁输出默认写入：

- `out/release-gates/`

其中包括：

- `local-runtime-smoke-*.json`
- `release-gate-local-runtime-*.json`
- 如果脚本托管启动了 LocalAgent，还会写入 `localagent-smoke-*.log`

`local-runtime-smoke-*.json` 还会额外记录临时 YAML 清理结果，包括：

- `thresholds`
- `threshold_results`
- `cleanup_removed_count`
- `cleanup_removed_paths`
- `cleanup_removed_preexisting_count`
- `cleanup_removed_preexisting_paths`
- `cleanup_failed_count`
- `cleanup_failed_paths`
- `out_cleanup_removed_count`
- `out_cleanup_removed_paths`
- `out_cleanup_removed_preexisting_count`
- `out_cleanup_removed_preexisting_paths`
- `out_cleanup_failed_count`
- `out_cleanup_failed_paths`

这些文件用于：

- 发布前留档
- 失败后回看具体轮次
- 对比不同提交的稳定性结果

## 7. 当前边界

这套门禁已经能回答“当前主链路有没有基本跑通”，但还不是最终形态。当前仍有以下边界：

- 轮次统计还没有长期趋势汇总
- 当前 CI 先以 `workflow_dispatch` 手动触发为主，尚未默认接入 PR / push 阶段
- 当前默认样例偏向 C# 节点路径，尚未覆盖更多类型的 dataflow
- 状态一致性还没有加入 WebSocket 与 HTTP 的交叉校验
- 标准阈值当前采取保守策略，要求 100% 通过；后续如果要面向更大范围环境推广，可能还需要基于历史统计再微调

因此，当前门禁更适合作为：

- 本地发布前检查
- 回归验证入口
- 稳定性收口阶段的最小基线

而不是最终版的全量质量平台。
